# Implementation Plan: RenderCV resume source

**Spec**: `./spec.md`
**Status**: Ready

## Technical Context
- Blog: Eleventy 3 on Node 24 (`.nvmrc`), with tests run through `node --test tests/*.test.cjs` (`package.json`). CI is `.github/workflows/test.yml`.
- New tool: RenderCV 2.8, a Python >= 3.12 CLI. The `[full]` extra bundles the Typst compiler (the `typst` Python wheel) and fonts, so no system TeX or Typst is needed.
- Local Python is 3.13. The CI runner uses `actions/setup-python` 3.13.

## Architecture & Approach
| Requirement | Change |
|---|---|
| FR-1 | `resume/David_Vasandani_CV.yaml`, generated by `rendercv new`, with contact details from `authors/david-vasandani.md` and `_data/metadata.json`. Sections are skeletons with TODO content. `design.theme: classic`. |
| FR-2 | `resume/requirements.txt` → `rendercv[full]==2.8`. The `resume:setup` npm script runs `scripts/resume.cjs setup`, which creates `resume/.venv` and installs the pinned requirements. |
| FR-3, FR-4 | `scripts/resume.cjs render [--watch]` runs `rendercv render David_Vasandani_CV.yaml` with `cwd: resume/`, so output lands in `resume/rendercv_output/`. Exposed as `npm run resume` and `npm run resume:watch`. |
| FR-5 | The wrapper uses `resume/.venv/bin/rendercv` (or `Scripts\rendercv.exe` on Windows), then `rendercv` on PATH. If neither exists, it prints how to run `npm run resume:setup` and exits 1. |
| FR-6 | Add `resume/` to `.eleventyignore`. Add `resume/.venv/` and `resume/rendercv_output/` to `.gitignore`. |
| FR-7 | New `resume` job in `test.yml`: checkout, setup-python with pip cache keyed on `resume/requirements.txt`, pip install, render, `test -s` on the PDF, `actions/upload-artifact@v4`. |
| FR-8 | `tests/resume.test.cjs` checks the exact pin, the YAML schema/name/theme, the ignore rules, and that `_site`/`_gemini` contain no resume files. It runs inside the existing `npm test` glob. |
| FR-9 | `resume/README.md`. |

## Data Model
Not applicable beyond RenderCV's own YAML schema. The file's `yaml-language-server` header links the v2.8 JSON schema.

## Contracts
CLI contract (`scripts/resume.cjs`):
- `setup`: exit 0 once the venv exists and requirements are installed.
- `render`: exit with RenderCV's status. Prints setup help and exits 1 if RenderCV is missing.
- `render --watch`: same as `render`, but stays running.

## Constitution Check
1. The change is confined to blog. 2. URLs and outputs are unchanged, and the test proves it. 3/4. The new test is deterministic, needs no credentials and publishes nothing. 5. RenderCV is pinned and documented. No npm dependency is added, so the lockfile is unchanged. 6. `.eleventyignore` excludes resume docs. 7. Python is pinned in an ignored venv and gets a separate CI job. The Node job does not need Python. 8. Codex review, knowledge base update, then PR. No deviations.

## Risks & Dependencies
- Typst wheel availability on Linux: verified by installing locally on x86_64.
- `settings.current_date: today` makes PDFs differ by date. Acceptable because output is not committed.
- Branch protection on `main` (signed commits, linear history) may require recreating the commits through the GitHub API (see knowledge base).
