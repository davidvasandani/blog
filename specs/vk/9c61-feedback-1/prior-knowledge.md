## Rules that bind this restructure

- **Voice** (resume voice page, constitution principle 10). Every changed line goes through `/voice`; "AI" at most once per line; no dashes or curly quotes; keep qualifiers ("reported", "postponed", "about", "roughly", "fell") and ownership word for word; write a before-and-after table with a facts column. Two mistakes the knowledge base warns about: an outcome slipping in while simplifying a vague benefit, and a causal rewrite dropping the subject. Both matter here because the task rewrites vague outcomes on purpose; the rewrite must describe the operational change, not invent a result.
- **David-supplied wording** (resume voice page). "Dozens of high-volume stores", "during the lunch rush", "the fleet of nearly 300 restaurants" and the loyalty DLL "logs nothing when the reward dialog opens" are his phrases. Use them as given; suggest style changes in the PR; record in the spec when a claim comes from his instruction rather than evidence.
- **Measured outcomes** (resume voice page, STAR section; hiring STAR page). A number goes on the resume only with a source row. Estimates only David can make (licensing avoided, hours returned, lost sales, headcount) are listed for him in hiring and never invented. Facts he removed on 2026-11-02 were restored on 2026-11-04 because he asked for measured outcomes; this task keeps them and only reorders or compresses around them.
- **Confidentiality** (resume voice page, hiring STAR page). The hiring repository's confidential lists apply to everything committed in the blog: specs, knowledge pages, commit messages and file names. Grep tracked and untracked changes (`git diff --name-only origin/main` plus `git ls-files --others --exclude-standard`), because the 2026-11-04 review caught two private file names that a plain diff grep missed. Never name the POS vendor, even by its short name.
- **Relevance** (relevance audit page). Keep relevance to the Netflix role, strength of evidence and chronology as three separate judgments. For this role the core is hands-on API integration, structured troubleshooting, targeted reusable fixes, stakeholder education, practical AI use and manual unblock work; generic infrastructure cost savings must not displace partner-support evidence. Locations can include labs (343 POS locations are not 343 restaurants); requeued is not completed; Python or Java and SQL need explicit proof, and tool names are not proof.
- **Role attribution** (role timeline page). Dates come from the HR effective history. The 2019 to 2021 bullets were imported from the 2021 resume and are not independently verified; preserve that provenance rather than redistributing them. Earlier employers fall outside the audited timeline; the hiring audit marks the 2016 to 2018 overlap as needing employment-arrangement context if asked, not as an inconsistency. The leadership-gap bullet is retained but not newly verified.
- **Release versions** (RenderCV page). Bump `resume/VERSION` with the change: major for restructuring or changed positioning, minor for additions, patch for corrections. Use the npm wrapper so the version marker is written; render before `npm run build`.
- **RenderCV quirks** (resume voice page, STAR section). A colon followed by a space in an unquoted highlight breaks the YAML. Long entries need `design.entries.allow_page_break: true`. A second paragraph in an entry summary renders as raw monospace text, so a role summary stays one paragraph.
- **Projects catalog** (projects page). `pages/projects.md` mirrors the resume's project descriptions; keep it aligned when a description changes, and do not imply ownership of upstream tools.
- **Page transform** (RenderCV page, task 0d66). `scripts/resume-page.cjs` folds location, dates and the optional duration line into one meta paragraph and turns a `**Theme: ...**` paragraph into a callout. Both are optional in the transform, and its tests use synthetic markdown, so removing themes and durations from the source needs no script change.
